# 快准车服查询 Agent 接口文档

本目录只记录快准车服上游接口，面向本项目的“快准车服查询 Agent”。最近采集时间为 2026-08-19，证据来自已登录的快准车服站管家 v2.0 页面、页面正常查询操作产生的网络请求、经用户授权分析的页面已加载模板/组件与 JavaScript bundle 中的查询字段配置，以及对已触发只读请求的最小化同源复核。后者只用于确认成功谓词和空容器形态，不用于猜新接口或提升原有证据等级。kzmall-plus Worker 自有接口、鉴权和错误协议统一放在[项目 API 文档](../project-api/README.md)。

## 使用约定

- 文档中的路径均相对于快准车服基地址 `https://dgj8.kzmall.cc/index.php`。经本项目调用时在前面加 `/api`；项目代理的认证、请求隔离、重放和错误语义见[项目 API 文档](../project-api/README.md)。
- 快准页面会话使用 Cookie 鉴权。不要把 Cookie、Token、用户信息或真实业务记录写入日志、提示词或持久化文档。
- A/B 只表示取证完整度，不代表 Agent 已能直接调用；是否可执行还要看下文的“线路可执行性”。任何写操作都必须另行审核业务影响与重复执行风险。
- `nd` 是页面生成的时间戳型防缓存参数，不属于业务过滤条件。
- jqGrid 风格接口常用 `_search`、`rows`、`page`、`sidx`、`sord` 处理搜索、分页和排序。
- 页面虽可能使用 `POST` 执行查询，仍应按“只读查询”对待；不得把路径或参数改造成保存、编辑、删除、审核、导入、调拨、开单等动作。

## 证据等级

| 等级 | 含义 |
|---|---|
| A | 通过页面正常打开/查询抓到真实请求，并从非空响应或正式 schema 确认行字段；UI 映射由模板 `v-model` / `prop`、查询对象或 jqGrid `colModel` 交叉验证 |
| B | 抓到真实请求，且 UI 条件/列字段已由模板或组件配置确认，但响应为空、编码载荷尚未解码，或字段类型/可空性仍不完整 |
| FR | 已抓到 FineReport 等会话化报表协议、参数提交和渲染列，但它不是可跨会话复用的稳定业务 REST |
| C | 仅确认页面入口、查询控件、结果列或 bundle 查询契约；主接口请求未被正常抓包证明 |
| X | 非查询入口，或属于会改变业务状态的流程，按安全要求未进入/未操作 |

证据等级只回答“文档依据有多完整”，不回答“脱离页面后能否在线路上解析和闭合入参”。FR 级只能描述报表协议和 UI 契约，不得硬编码 `viewlet`、会话参数或把 `page_content` 冒充业务 JSON。C 级页面只能用于描述产品能力，获得后端正式契约或正常页面请求证据前不得生成可执行调用。

## Agent 线路可执行性

| 状态 | 含义 | Agent 行为 |
|---|---|---|
| 可执行 | 请求体、成功谓词、列表/分页路径和所用筛选值来源均闭环；响应是普通 JSON 或已有正式的服务端解析契约 | 可进入只读 HTTP 工具白名单 |
| 条件可执行 | 默认请求可复现，但个别枚举、动态选项、多选线格式或完整翻页终止条件尚未闭环 | 只暴露已确认条件；未知条件固定为空或省略。分页未闭环时只允许有界第一页，并显式返回“可能截断”，不得自动翻页 |
| 页面会话依赖 | 原始响应依赖页面会话状态、页面内密钥或会话化报表协议 | 不生成纯 HTTP Agent 工具；只能在受控页面流程或正式适配层中使用 |
| 不可执行 | 请求/响应契约不足、仅有 C 级入口证据，或属于写流程 | fail closed，不发请求 |

A/B 是进入评估的必要条件，不是充分条件。例如商品和车型候选接口虽然已有 A/B 级页面证据，但原始 `data` 是依赖页面会话 `SYSTEM.k` 的 `kziv` 字符串，在项目提供正式服务端解码适配前属于“页面会话依赖”。主查询若依赖这类候选值，也只能在调用方已经安全持有确切 ID/编码时使用对应筛选。

每个实现必须同时检查证据等级和线路状态。章节没有写明成功谓词、数据容器，或所用筛选没有闭合到精确线格式时，一律不得把 HTTP 200 当成“查询成功且无数据”。

## 请求表解释规则

- 章节中的完整 HTTP 示例是该页面当前线路的规范请求形态。示例出现 `key=` 表示空值也发送该键；正文明确写“省略”才允许不发送。
- JSON 中的 `""`、空数组、缺键，表单中的零字节 body、空表单和无 `Content-Type` 不是同一种形态，不得相互替换。
- 多选必须写明逗号分隔、重复键或 JSON 数组字符串。仅写“集合”而没有线格式的筛选，Agent 不得暴露。
- 固定枚举只有在值域完整且无冲突时才可暴露；值域缺失或页面与响应元数据冲突时，保留已确认默认值并隐藏该筛选。
- 排序字段只允许章节列出的值；没有 allowlist 时固定使用页面默认排序，不接受用户直接传入任意 `sidx/sortWay`。

每个可执行列表页应尽量沉淀两张标准映射表：

1. `UI 筛选项 | 请求参数 | 类型 | 默认值/枚举及空值形态 | 释义 | 证据`；
2. `响应字段/路径 | 类型/可空 | 表格列 | 格式/单位 | 释义 | 证据`。

凡筛选参数需要客户、员工、仓库、商品等内部 ID 或业务编码，还必须在[查询参数 ID / 编码来源](./lookups.md)中闭合“消费参数 → 候选接口 → 提交字段 → 显示字段”；同名参数存在页面差异时按消费页面分别记录。

空结果页面可以用模板/组件 `prop` 确认字段名和列名，但类型与可空性必须标为“待非空响应确认”，不能仅凭列配置臆测。

## Agent 查询预算

以下数值是本项目的 Agent 数据最小化策略，不是对快准后端能力的推断。网页为本地表格加载而设置的 `rows=3000`、`rows=1000000` 或 `loadonce` 不是 Agent 默认值。工具实现必须执行以下硬限制：

- 有可靠服务端分页的端点：单次 `rows/limit` 不超过 `200`，按页继续；每次响应最多读取 `2 MiB`，超限即停止并返回“结果过大/需缩小条件”，不得自动改成更大的页。
- 只有 `page/records/total`、`count/page_count` 等总数/总页路径已确认时，才可宣称完整翻页。仅接受 `page/rows` 但响应没有可靠分页元数据的接口，不得用“短页/空页”经验规则自动续页；只取有界第一页并返回 `pagination_complete: false`，要求用户缩小日期或增加业务条件。
- 日期报表默认最多查询连续 `31` 天。没有可靠分页、页面使用近似全量行数的销售明细、销售汇总和商品收发报表，最多 `7` 天，并且优先要求客户、商品或仓库中的至少一个窄化条件。
- 章节只证明了页面超大行数、没有证明较小 `rows` 生效时，不得宣称可稳定续页；达到行数/字节上限后必须标记结果可能截断，并让用户缩小范围。
- 不得为了“补全”自动导出、切换成本/毛利端点或扩大日期范围。成本、财务和个人信息字段仍按最小必要原则返回。
