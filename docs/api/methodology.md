# 采集方法与安全边界

## 授权范围

本次仅允许：

1. 打开并切换快准车服后台页面；
2. 展开菜单；
3. 编辑查询表单；
4. 点击文本明确为“查询”或“搜索”的触发器；
5. 读取页面可见的查询条件、结果表头、分页控件；
6. 记录上述正常 UI 操作产生的 Document/XHR/Fetch 请求及响应结构；
7. 在 2026-08-18 用户补充授权后，读取页面模板和已加载 JavaScript bundle 中与查询契约直接相关的 Vue `v-model` / `prop`、查询对象、jqGrid `colModel` 和站点正式响应处理函数，用于建立 UI 与接口字段的逐项映射。
8. 在 2026-08-19 的闭环复核中，只对已经由正常页面触发并已记录的只读请求做同源登录会话重放；日期缩到单日、页大小缩到最小，仅提取 HTTP 状态、业务成功值、顶层键和容器类型，用于补齐成功谓词与空结果形态。
9. 在纯净上下文审阅提出请求头和分页疑点后，再次通过正常页面打开“库存查询”和“大客户销售退货单查询”；网络证据只抽取对应 XHR 的方法、请求头名称、零字节 body、成功状态和响应外层，并用页面已加载查询脚本的 `jsonReader` 交叉验证列表/分页路径，不把业务行值写入仓库。

## 明确禁止

- 不点击或调用新增、保存、确认、提交、编辑、删除、审核、作废、导入、导出、调拨、组装、拆包、开单、退款、支付等动作。
- 不猜测、枚举或重放页面未实际触发的隐藏接口。
- 不读取浏览器 Cookie、Local Storage、密码、会话存储或浏览历史。
- 不在仓库中保存真实客户、联系人、电话、地址、账号、单据号、商品明细、库存、金额或利润数据。

## 抓包流程

1. 以当前网络事件游标为基线；
2. 从顶层菜单点击一个明确的查询/管理/报表叶子入口；
3. 过滤静态脚本、样式、图片、字体、统计和浏览器扩展请求；
4. 读取过滤区控件、下拉值域、分页设置和结果表头；
5. 只有在触发器文本严格等于“查询”或“搜索”时才点击；
6. 增量读取该动作产生的站点内 Document/XHR/Fetch；
7. 对 JSON 响应只抽取容器键、字段名和数据类型，不持久化行值；
8. 用页面模板、组件查询对象、Vue `prop` 或 jqGrid `colModel` 交叉验证“UI 条件 -> 请求参数”和“响应字段 -> 表格列”；
9. 对每个内部 ID/业务编码筛选项，同步确认候选接口、选项响应中的提交字段和显示字段，并写入[查询参数 ID / 编码来源](./lookups.md)；不能仅凭 `Id` / `No` 后缀推断；
10. 对站点编码字符串，可分析前端公开加载的解码调用和字段配置来补充契约，但不得在仓库保存解码后的真实业务记录。
11. 对 FineReport，只记录当前会话真实产生的入口、参数提交键和渲染列；不保存 `viewlet`、站点编码、会话标识或页面片段中的业务行值。
12. 已记录查询的同源重放不能替代原始 UI 抓包来证明路径、方法、请求头或入参，也不单独提升 A/B/C 等级；若重放结果与既有文档冲突，以 fail closed 方式记录差异并等待正常页面复核。

## 脱敏规则

- 日期示例统一使用 `<YYYY-MM-DD>`。
- ID、编码、单号统一使用 `<id>`、`<code>`、`<billNo>`。
- 名称统一使用 `<customer>`、`<goods>`、`<brand>` 等语义占位符。
- 数量和金额统一使用 `0` 或 `<number>`，不复制线上真实值。
- URL 中的 `nd` 使用 `<timestamp>`。
- 请求头只记录业务上必要的约定，不记录任何实际 Cookie 或 Authorization 值。

## 已知限制

- 部分老页面把 JSON 封装在顶层 `data` 字符串中，并使用站点自有编码。快准/三方商品页已确认站点正式 `processData → aesDecrypt → JSON.parse` 调用，并只在页面内提取解码后的字段名和类型；其他页面若尚未确认正式处理调用，仍将载荷标为 `opaque`。
- FineReport 的 `parameters_d` / `page_content` 依赖当前 `viewlet` 和报表会话。即使抓到真实请求，也标为 FR，而不是稳定业务 REST。
- 空结果无法单独证明行字段的实际类型与可空性；此时以页面模板/组件列配置作为字段名证据，并在文档中标为 B，直到取得非空响应或正式 schema。
- 菜单名称为“管理”并不自动代表写接口。列表自动加载和查询动作可以采集，但行内编辑/删除等操作始终排除。
- 本文档反映截至 2026-08-19 当前账号、当前服务站权限下可见的页面；后端版本或权限变化后应重新用相同只读流程复核。

## 旧文档缺少逐项映射的原因

早期文档主要沉淀正常 UI 查询产生的 URL/请求体和页面可见中文表头，当时的授权范围又排除了 JavaScript bundle 取证，因此没有读取 Vue 查询对象、输入组件 `v-model`、表格 `prop` 或 jqGrid `colModel`。这会造成两类断点：一是只能知道“页面有客户、状态等条件”，却无法证明它们分别对应 `buId`、`billStatus` 等参数；二是空列表响应没有 `rows[]` 行样本，只能记录中文列名，无法证明 `contactName`、`totalAmount` 等响应字段。

2026-08-18 获得补充授权后，逐项映射改为用三类证据交叉验证：真实抓包证明请求和值的默认形态，非空响应证明字段类型/可空性，页面模板或组件配置证明 UI 条件/表格列与接口字段的对应关系。任一环缺失时继续保留 B/C 级和“待补证”标记。
